# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal macOS dotfiles repository. It installs Homebrew packages and symlinks config files (zsh, git, VS Code) from this repo into their expected `$HOME` locations. There is no build, test, or lint step — the "product" is the shell scripts and the config files themselves.

## Layout & install model

Each tool lives in its own directory under `.config/<tool>/` and owns an `install.sh` that follows the same pattern:

1. Compute `SCRIPT_DIR` from its own location (`cd "$(dirname $0)"`).
2. Back up the existing target file into `<tool>/backup/` (this dir is gitignored — see `.gitignore`).
3. `rm` the target, then `ln -s` the repo copy into place.

So editing a config here takes effect immediately on the machine (the live file is a symlink into the repo). Re-running an `install.sh` only re-creates the symlink; it does not need re-running after edits.

- `.config/zsh/` — `.zshrc` → `~/.zshrc`
- `.config/git/` — `.gitconfig` → `~/.gitconfig`, `.gitignore_global` → `~/.gitignore_global`
- `.config/Code/` — `settings.json` and `keybindings.json` → `~/Library/Application Support/Code/User/`. Its `install.sh` also installs every extension listed in `extensions` (one ID per line) and rewrites `extensions` from the currently-installed set afterward.

## Bootstrapping a new machine

`setup.sh` is the top-level bootstrap: installs Homebrew → `brew bundle` (from `Brewfile`) → nodenv + `nodenv-yarn-install` plugin → oh-my-zsh.

Known gap: `setup.sh` ends by calling `.config/install.sh`, which does not exist. The per-tool `install.sh` scripts must currently be run individually.

## Key details when editing

- **`Brewfile`** is the source of truth for installed packages (~110 formulae/casks). Regenerate with `brew bundle dump --force` if reflecting the current machine.
- **VS Code `extensions`** is regenerated by `.config/Code/install.sh` on each run — don't hand-edit it as the primary source; change the installed set and re-run.
- The zshrc assumes `robbyrussell` oh-my-zsh theme, `anyenv` (nodenv/goenv/pyenv/rbenv/jenv), Volta, bun, Rancher Desktop, and gcloud — many `eval "$(... init -)"` lines. It sources `~/.pzshrc` at the end for machine-private secrets that should stay out of this repo.

## Secrets

Machine-private secrets belong in `~/.pzshrc` (sourced at the end of `.zshrc`), never in tracked files.

Historical note: a `GREN_GITHUB_TOKEN` was previously hardcoded in `.config/zsh/.zshrc`. It has been removed from the working tree but still exists in git history and must be revoked at https://github.com/settings/tokens. If any secret is found in a tracked file, flag it rather than committing over it.
