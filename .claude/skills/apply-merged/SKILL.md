# apply-merged

マージした PR の変更を `$HOME` に配る。素の `chezmoi apply` を使わないのは、次の 2 つで事故が起きるから。

- chezmoi のソースはこのリポジトリのチェックアウトで、作業中のブランチにいることがある。そこで apply すると
  マージしていない変更まで配り、マージした変更は配られない
- `~/.claude/settings.json` など、アプリが自分で書き換えるファイルはライブ側に追跡外の変更が溜まっている。
  丸ごと apply するとそれが消える

## 1. スクリプトを流す

```bash
scripts/apply-merged.sh <PR番号>
```

PR 番号が分からなければ `gh pr list --state merged --limit 5` で確かめる。様子だけ見たいときは `--dry-run`。

スクリプトは origin/master を一時的な worktree に出し、PR が `home/` で変えたファイルを 1 つずつ判定する。
出力は `<状態>\t<配備先>` で、状態ごとに次のように扱う。

| 状態 | 意味 | すること |
|---|---|---|
| `applied` | ライブが PR の前の内容のままだったので apply した | なし |
| `up-to-date` | すでに PR の後の内容 | なし |
| `conflict` | ライブが PR の前とも後とも違う（アプリか手で変えた） | 2 で PR の変更分だけを足す |
| `removed` | PR で消したファイル（chezmoi は消さない） | 3 で消すか聞く |

終了コード 3 は conflict か removed が残っていることを表す。stderr の「install スクリプトが変わっている」は
3 の報告に含める（スクリプトは install を実行しない）。

## 2. conflict に PR の変更分だけを足す

スクリプトは PR の前後の内容を `CONFLICT_DIR`（stderr に出る）に `<配備先の / を % にした名前>.{old,new}` で残す。
`.new` でライブを上書きしない。ライブ側の追跡外の変更が消える。

1. `diff -u <.old> <.new>` で PR の変更分を読む
2. ライブのファイルに、その変更分だけを当てる
   - JSON（settings.json など）は jq で該当のキーだけを足す・変える。足す前に、同じものが既に入っていないかを確かめる
   - テキストは `diff -u <.old> <.new> | patch --dry-run <ライブ>` で当たるかを見てから当てる
   - 当たらない、または PR の変更とライブの変更が同じ箇所を触っているときは、当てずに差分を見せてユーザーに聞く
3. 当てる前にライブのファイルをスクラッチパッドに写しておき、報告にそのパスを書く

ライブ側の追跡外の変更を追跡に取り込みたいなら `chezmoi re-add <配備先>` だが、リポジトリに差分が出るので
勝手にはしない。報告で勧めるだけにする。

## 3. removed を片付ける

ファイルを消すのは戻せない操作なので、消してよいかをユーザーに聞いてから消す。

## 4. 報告する

- 状態ごとのファイルの一覧
- conflict に当てた変更と、写しの置き場
- 実行していない install スクリプト、消していないファイル
