# writing-retro

ユーザーは AI に書かせた文章へ毎日同じような指摘を入れている。指摘はそのセッションの中でしか
効かないので、翌日の別のセッションはまた同じ書き方をする。このスキルは 1 日の終わりに全セッションの
指摘を集めて一般化し、`~/.claude/rules/writing.md` に書き足す。このファイルは Claude Code が
全プロジェクト・全セッションで自動で読み込むので、書いた翌日から効く。

スクリプトは `~/.claude/skills/writing-retro/scripts/retro.sh`、作業データは
`~/.claude/writing-retro/` に置く。`~/.claude/rules/writing.md` も作業データも dotfiles では
追跡しない。業務のセッションでの指摘から作るので、公開リポジトリには置けない。

**機械的に決められることはスクリプトに任せ、Claude は候補の判定と一般化だけをする。**
発言の抜き出し、指摘の候補の絞り込み（`references/lexicon.txt` の語に当たるか）、何を書いた
直後か（媒体）の判定、回数の集計、ルール件数の確認はスクリプトが行う。全件を読ませると毎日
150 件前後になるが、絞り込めば 10 件前後で済む。

## 手順

### 1. 抜き出す

```bash
~/.claude/skills/writing-retro/scripts/retro.sh extract
~/.claude/skills/writing-retro/scripts/retro.sh list
```

`extract` は前回の振り返り以降（初回は当日 0 時以降）にユーザーが打った発言のうち、
`lexicon.txt` の語に当たるものだけを集める。過去分を読みたいと言われたら `--since 7d` を渡す。
`list` は 1 件につき「id、時刻、媒体、作業ディレクトリ、発言」の行と、`←` で始まる直前の
AI の発話の末尾を出す。媒体は直前に AI が書いたもの（`pr` `notion` `slack` `md` `commit`
`github` `doc`、何も書いていなければ `chat`）。

**`messages` が 0 なら、ルールファイルも読まずに 7 の commit だけして終わる。**

### 2. 指摘を選ぶ

`list` の全件に目を通し、**AI が書いた文章の書き方への指摘**を選ぶ。対象は PR 本文、
Notion や kb のページ、Slack の文面、コミットメッセージ、コードコメント、チャットでの説明。

拾うもの:

- 分かりにくさの指摘（「分かりにくい」「省略しないで」「何が言いたいの」）
- 書き方・構成の指示（「箇条書きにして」「結論から」「リンクにして」「表にして」）
- 読み手を基準にした直し（「初見でも分かるように」「この用語は通じない」）
- ユーザーが自分で書き直した文を貼ってきた場合の、書き直しの差分

拾わないもの:

- 事実の誤りの訂正、作業内容の指示、コードの直し
- その文書にしか当てはまらない中身の注文（「この節に○○の件も足して」）
- この振り返りのセッション自身での発言

判定は `list` に出る発言と直前の発話の末尾で行う。`retro.sh context <id>` で全文を引くのは、
末尾だけでは何を書いたときの指摘か分からないものに限る。

### 3. 一般化する

拾った指摘ごとに「次から何をすればこの指摘を受けずに済んだか」を 1 文のルールにする。

- 肯定形で書く（「〜しない」ではなく「〜する」）。禁止が要るなら、代わりにどうするかを添える
- 具体的に書く。「分かりやすく書く」のような、守ったかどうか判定できない文は書かない
- 元の指摘の言葉を短い例として添える。ルールファイルは追跡していないので、固有名詞や URL を
  伏せずにそのまま書いてよい（具体的なほうが効く）。パスワードやトークンなどの秘密だけは書かない
- 媒体を問わないものは「共通」、特定の媒体だけのものはその見出しに置く

同じ日に同じ趣旨の指摘が複数あれば 1 つのルールにまとめる。

### 4. 既存のルールと照らし合わせる

`retro.sh init` でルールファイルが無ければ雛形から作り（新しいマシンでは無い）、
`~/.claude/rules/writing.md` の全文を読んで、拾った指摘を次のどれかに振り分ける。
strengthened が 1 件でもあるときだけ `retro.sh stats`（ルールごとのこれまでの指摘回数）を見る。

- **added**: どのルールにも当たらない。新しいルールとして足す
- **strengthened**: 既にルールがあるのに指摘された。ルールが効いていない証拠なので、
  文言を具体的にする、NG/OK の例を足す、より目に付く位置へ移す、のどれかで書き直す。
  `stats` で 2 回目以上なら、書き直し案に「○回目」と添える
- **skipped**: 一般化できなかった。理由を 1 行で残す

explain-before-shorten や yomiyasu が既に扱っている観点でも、指摘されたなら strengthened 扱いで
ルールに書く。スキルが発火しなかった、または発火しても直らなかったということなので。

### 5. 承認を取る

追加と書き直しの案を、ルールごとに「元の指摘（日付・発言）→ ルール案」の形で見せ、
AskUserQuestion の multiSelect で採否を 1 回で聞く。案が 4 件を超えるなら、本文に全件の案を
番号付きで並べ、採用する番号をまとめて聞く。

### 6. 書き込む

採用されたものを `~/.claude/rules/writing.md` に反映する。

- ファイルの既存の見出しと粒度に合わせる。1 ルール 1〜2 行、例を付けても 4 行まで
- 書く前に `retro.sh budget` を見る。`over` が true なら、足す前に似たルールをまとめる案を
  5 の承認に含める。このファイルは毎回のセッションで読み込まれるので、長くなるほど
  全セッションのトークンが増え、他の指示も埋もれる

### 7. 記録して既読にする

判定した指摘を JSON 配列でスクラッチに書き、log に残してから cursor を進める。

```bash
~/.claude/skills/writing-retro/scripts/retro.sh log /path/to/entries.json
~/.claude/skills/writing-retro/scripts/retro.sh commit
```

entries の要素は `{"quote": 元の発言, "action": "added|strengthened|skipped", "rule": 当てたルールの文,
"reason": skipped の理由, "session": セッション id}`。却下されたものも `skipped` で残す。
`stats` は `rule` の文字列で集計するので、strengthened では書き直す前のルール文ではなく
**書き直した後の文**を入れる。

**commit は log の後にだけ実行する。** 先に commit すると、判定に失敗した日の発言が二度と読まれない。

### 8. 報告

「読んだ発言 N 件（候補 N 件）/ 指摘 N 件 / 追加 N 件 / 書き直し N 件 / 見送り N 件」を 1 行で出し、
書き直したルールがあれば、何回目の指摘だったかを添える。

## 漏れの点検

`lexicon.txt` に無い言葉で入れた指摘は候補に上がらない。週に 1 回程度、ユーザーに頼まれたときに
`extract --since 7d --all` と `list --short` で全件を流し読みし、候補から漏れていた指摘を探す。
見つかったら、その指摘に使われていた言葉を `lexicon.txt` に足す案を出す。足したら
`chezmoi re-add ~/.claude/skills/writing-retro/references/lexicon.txt` でソースへ戻す。
全件を読むのはこのときだけにする。点検では log も commit もしない（cursor は毎日の振り返りのものなので）。
