# learning-code

AI が書いた PR を任せきりにせず、**自分の言葉で説明できる状態**にするための出題・記録スキル。

データの読み書きは `scripts/skills-db.sh` に寄せてある。ここに書くのは**モードの振り分けと、
毎回判断が要る部分**だけ。出題・採点の手順は `references/quiz.md`、判定基準は `references/levels.md`、
データ構造と昇降格のルールは `references/schema.md` にある。**出題の前に必ず該当リファレンスを読む。**

## 0. モードを決める

```bash
scripts/skills-db.sh init    # 冪等。まず必ず走らせる
```

| 引数 | モード | やること |
|---|---|---|
| なし（PR の無いブランチ） | ダッシュボード | §1 |
| なし（現ブランチに PR がある） | PR 駆動 | §2。ただし**対象 PR を提示して確認してから**始める |
| 数字 / `#123` / PR の URL | PR 駆動 | §2 |
| `review` / `復習` | 復習 | §3 |
| 上記以外の文字列 | 領域指定 | `skills.json` に無ければ §4、あれば §3 をその領域に絞る |

現ブランチの PR は `gh pr view --json number,title,url` で見る（無ければ非ゼロで落ちる）。

## 1. ダッシュボード

```bash
scripts/skills-db.sh show                 # 全体
scripts/skills-db.sh show <領域>           # 1 領域の項目一覧（メモは 40 字で切り詰め）
scripts/skills-db.sh show --full <領域>    # 判定根拠を全文で見る
```

出力をそのまま貼り、下に **3 行だけ**所見を足す: 弱い領域、放置が長い項目、次にやるとよいこと。
記録が空なら、出題を始めるには PR 番号か領域名を渡せばよいと案内して終わる。

**Artifact は作らない。** ターミナルのテキスト表で完結させる。

## 2. PR 駆動

1. `gh pr diff <番号>` で差分、`gh pr view <番号> --json title,body` で意図を読む
2. `references/quiz.md` の §C に従って topic を 3〜5 個切り出す。
   **既知スタック（react/typescript/laravel/mysql）の定型は除外する**
3. 切り出した topic を一覧で見せ、合意を取る
4. 各 topic の領域が `skills.json` に無ければ、その領域だけ先に §4（初期判定）を走らせる
5. `references/quiz.md` の §B に従って記述式で出題・採点し、1 項目ごとに `upsert` で保存
6. 最後に「この PR で説明できるようになったこと / まだ怪しいこと」を各 3 行以内でまとめる

差分が大きいときは全部扱わない。**理解の穴になりそうな順に 5 個**で打ち切り、残りは次回に回す。

## 3. 復習

```bash
scripts/skills-db.sh due [領域]    # TSV: 領域 / topic / レベル / 最終評価日 / 経過日数 / メモ
```

返ってきた中から**レベルが低い順 → 経過日数が長い順**で 3〜5 個選び、§B の記述式で出題する。
`note` に前回の判定根拠が入っているので、**そこを狙って深掘りする**（同じ問いを繰り返さない）。
`due` が空なら、その旨と次に期限が来る項目を伝えて終わる。

## 4. 初期判定（未知の領域）

`references/quiz.md` の §A に従って **4 択 5 問**を `AskUserQuestion` で 1 問ずつ出し、
正答数から初期レベルを決めて `upsert` で保存する。
領域名はユーザーの言葉のまま使わず、**検索できる粒度に正規化する**（`Rails` → `rails`、
`テスト周り` → 何のテストか聞く）。

## 守ること

- **答えを先に出さない。** コードの解説を長々と書くとこのスキルは意味を失う。
  聞く → 答えてもらう → 足りない観点だけ補う、の順を崩さない
- **1 セッション 3〜5 topic で切る。** 網羅しようとすると精度も集中力も落ちる
- **判定には必ず 1 行の根拠を付ける。** 根拠は `upsert` の note にそのまま渡す
- **保存は 1 項目ごと。** まとめて最後に書かない
- `skills.json` を Edit ツールで直接いじらない。昇降格のルールを飛ばしてしまう
- ユーザーが「知らない」と即答した項目は `beginner` で記録して次へ。粘らない
