# COB — 今日の振り返りと演習

`/learning-code COB` で走るモード。その日に出題した内容を振り返り、**手を動かす演習**で
定着させるところまでをやる。読み返すだけで終わらせないのが目的。

## 手順

### 1. 今日の材料を集める

```bash
scripts/skills-db.sh tested            # 今日出題した項目 TSV: 領域/topic/level/last_judged/note/source
ls "$(scripts/skills-db.sh logs-dir)"  # 解説ログ
```

その日の解説ログ（`YYYY_MM_DD_*.md`）を読む。`tested` が空なら「今日は出題していない」と伝え、
直近の解説ログの日付と `due` の状況だけ示して終わる。**何も無い日に無理やり演習を作らない。**

### 2. 振り返りを出す

テキストで次を示す。**合計 15 行以内。**

- 今日測った項目の表（領域 / topic / レベル / どこで止まったか）
- レベルの内訳が今日どう動いたか（新規に測ったもの、上がったもの、下がったもの）
- **一番効く復習は何か**を 1 行

### 3. 演習をやるか聞く

`beginner` と `junior` の項目があれば演習を提案する。**全部はやらない。最大 2 件。**
選ぶ基準は「今日いちばん手前で詰まったもの」で、レベルが低い順。

やらないと言われたらそこで終わる。粘らない。

### 4. 演習（1 件ずつ）

**手を動かす形にする。** 解説を読み返させるのではなく、実行して結果を見せる。

演習の作り方は topic の性質で決める:

| topic の性質 | 演習の形 |
|---|---|
| 挙動が 1 コマンドで確かめられる（jq の式、シェルの構文） | **最小の再現コマンドを自分で組ませる。** 「`as` が `.` を変えないことを示す 1 行を書いて」 |
| 壊れ方を見せたい（`set -e`、リダイレクト） | **壊れた版を渡して直させる。** 実行して失敗を見せてから、原因を言ってもらう |
| イディオム（ソースガード） | **同じ効果を別の書き方で実現させる。** 書けたら、なぜ元の書き方が選ばれているか聞く |
| 概念・ドメイン知識 | コードにならないので、**自分の言葉で再説明 + 具体例を 1 つ作らせる** |

進め方:

1. 課題を出す。**答えのコードは出さない**
2. ユーザーが書いたものを**実際に実行して結果を見せる**（`/tmp` 配下などで。リポジトリは汚さない）
3. 期待と違えば、どこがずれたかだけ指摘してもう一度書いてもらう。**2 往復まで**
4. できたら `upsert` でレベルを付け直す。演習を通ったなら `source` は `COB` にする

演習で書けたからといって一気に senior にはしない。昇格は 2 回連続の上位判定が要る
（`references/schema.md`）。演習の判定も 1 回ぶんとして扱う。

### 5. 今日の分を閉じる

演習をやったら、その内容を解説ログに追記する（§ 解説ログの規約は `references/quiz.md` の §D）。
最後に次に期限が来る項目を 1 行で伝えて終わる。

## やらないこと

- 今日やっていない項目まで広げる（それは `review` モードの仕事）
- 解説の再掲で終わる（読み返しは定着しない。手を動かさせる）
- 演習を 3 件以上出す（COB は締めなので短く終える）
