# レベル判定のルーブリック

4 段階。保存は英語 enum（`beginner` / `junior` / `senior` / `professional`）、表示は日本語。

| 保存値 | 表示 | 判定基準 |
|---|---|---|
| `professional` | プロフェッショナル | 設計上のトレードオフを語れる。代替案と、それを採らなかった理由を自分の言葉で挙げられる |
| `senior` | シニア | 動作原理を説明できる。落とし穴・例外ケース・性能やメモリへの影響を指摘できる |
| `junior` | ジュニア | 何をしているかは説明できるが、「なぜその書き方なのか」が言えない |
| `beginner` | ビギナー | 読んで意味が取れない。または用語を借りただけで中身の無い説明になる |

## 著者の前提

判定はこの前提の上で行う。前提より下は測らない。

- 基本情報技術者。計算機科学の基礎（計算量、データ構造、トランザクション、HTTP、文字コード等）は既知
- Web 業界 10 年。設計レビュー・運用・障害対応の経験がある
- 日常のスタックは **react / typescript / laravel / mysql**

このため:

- **既知スタックの概念そのものは出題しない。** `useEffect` の依存配列や Eloquent のリレーションを
  聞いても測定にならない。対比として引用するのは可（むしろ推奨）
- **一般的なプログラミング基礎も出題しない。** 「クラスとは」「N+1 問題とは」は前提
- 未知言語でも、**言語固有の意味論に落とし込んで聞く。**
  「Ruby のブロックは何か」ではなく「このブロックは TypeScript のコールバックと何が違うか」
- 「知らない」と即答された項目は `beginner` で記録する。粘って引き出さない（時間が無駄になる）

## 判定でやりがちな間違い

- **用語が合っているだけで senior にしない。** 「メタプログラミングです」は名前を言っただけ。
  いつ壊れるか・何と競合するかを言えて初めて senior
- **流暢さに引っ張られない。** 長い回答でも、差分のコードを言い換えただけなら junior
- **1 問で professional を付けない。** トレードオフを聞く問いに答えられたときだけ
- **「なんとなく読めている」を Good にしない。** 既知スタックに似た書き方は、経験で雰囲気を
  当てられてしまう。引用した差分の具体（どの行・どの値・どの順）に触れていない回答は、
  内容が間違っていなくても `junior` 止まりとし、必ず深掘りしてから判定を確定する
- 判定は必ず **1 行の根拠つき**で返す。「代替案（〜）に触れたので senior」のように
