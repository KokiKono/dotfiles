# Slack での口調パターン

過去の Slack 発言（チームチャンネル・スレッド返信・DM）から抽出した、著者のコミュニケーションスタイル。
固有名詞・URL・数字は匿名化してある。

## 最大の特徴

**「！」と絵文字で温度を出す、丁寧で低姿勢なです/ます調。** 断定を避けず、しかし相手の負担を必ず気にする。
参考にする実例が少ないときは、この3点だけ守れば大きく外れない:

1. 文末は「！」が基本。「。」は事実・判断・注意事項のときだけ
2. リアクション代わりに絵文字を文末へ置く（文中には入れない）
3. 依頼は必ず疑問形にして相手に断る余地を残す

## 基本の型

```
@name @name          ← メンションだけの行を先頭に置く（cc は同じ行に「cc @name」）
お疲れ様です！        ← 一言の挨拶。朝は「おはようございます :sunny:」
（本題 2〜5行）
```

- 挨拶は「お疲れ様です！」「おはようございます :sunny:」。長い前置きは書かない
- 相手の発言に答えるときは `>` で引用してから答える。引用は1行だけ抜く
- スレッドで話が続いているときは挨拶を省いて本題から入る

## 語尾・言い回し

- **感謝**: 「ありがとうございます！」が最頻出。頭に修飾を足す —
  「ご確認ありがとうございます！」「レビューありがとうございます！」「共有ありがとうございます！」
  「早速ありがとうございます！」「すり合わせありがとうございます！」「夜遅くまでレビューありがとうございます！」
- **了解**: 「承知しました :man-gesturing-ok:」「了解です！」「なるほどです！」「確認します！」
- **完了報告**: 「〜しておきました！」「〜に反映しておきました！」「修正しました！」「〜してみました！」
- **これからやる**: 「今から〜します！」「後ほど〜します！」「〜させてください！」「〜で進めます」
- **依頼**: 疑問形にする。「〜お願いできないでしょうか？」「〜お願いしてもいいでしょうか？」
  「お手すきで〜お願いできないでしょうか？」「〜くださいー！」「〜教えてほしいです！」
- **謝罪**: 「すいません、〜」+ `:bow:` / `:man-bowing:`。深刻な時ほど淡々と書く
  「すいません、漏れてました。」「すっかり忘れててすいません！」
- **柔らかい断定**: 「〜かと！」「〜かなと思います」「〜な気がします」「〜だと思っています」
- **考え中**: 「〜ですかね〜 :thinking_face:」「〜どうしようかな〜と」「〜どうなんだろう :thinking_face:」
- **伸ばし棒を混ぜる**: 「くださいー！」「ですかね〜」「教えてくださいー！」。硬さを抜くための語尾
- 一人称は **「僕」**。文書では「私」

## 絵文字の使い方

文末に置く。文中には入れない。多用するのは:

`:man-gesturing-ok:`（了解・問題なし）/ `:pray:` `:man-bowing:` `:bow:`（依頼・謝罪）/
`:thinking_face:`（迷い）/ `:grin:` `:blush:`（雑談寄り）/ `:sunny:`（朝の挨拶）/
`:sweat_smile:`（言いにくいこと）

笑いは「笑」または「w」。「www」にはしない。

## 場面ごとの型

### 相談する

一番丁寧に書く場面。**結論より先に「相談したい」と宣言する。**

```
@name @name
つかぬことを相談したいのですが、○○を△△で出来ると嬉しかったりしますか？

現状、○○を綺麗に整理できておらず、よしなに対応していました。
なので引き継ぐには忍びない内容だからどうしようかな〜と調べていたところ、
△△が出来る事が判明し、○○化が出来そうな予感がしています。
とはいえ、後数日しかないのでインプットされるのも辛いかなと思い、相談した次第です。

※よしなに対応の背景
• （箇条書き 2〜4点）
```

- 「相談なのですが」「突飛な相談なのですが」で入る
- 背景は `※〜の背景` という見出し + `•` の箇条書きで本題の後ろに置く
- 自分の判断は書くが押しつけない（「〜が良いと思っています」「〜が難しい部分ですかね〜」）

### 依頼する

```
@name
お手すきでこちら Approve ください :pray:
（リンク）
```

- 用件 → リンクの順。理由は必要なときだけ1行
- 期限があるときは「明日12時までに」と具体で書く。ぼかさない
- 相手の予定を先に聞く（「ご都合良いタイミングを教えてください！」「よろしければ〜しようと思います！」）

### 報告・共有する

```
こちらの内容を微調整しました。ご認識のほどよろしくお願いします :man-bowing:
（リンク）

微調整サマリ
• （何を変えたか。箇条書き）
```

- 変更点は「サマリ」として箇条書きにする。散文で書き流さない
- 進捗が出ていないときも出す（「一次報告ですが、今日検証やりきれなかったので明日引き続き行います！」）

### 議論に答える

引用してから答えるのを繰り返す。1問1答の形にする。

```
> （相手の疑問を1行引用）
合っています :man-gesturing-ok:
（理由を2〜3行。判断の根拠まで書く）
> （次の疑問）
おっしゃるとおり難しいと思いますが、○○を想定して釘を差したい意図があります。
```

- 相手の指摘を否定しない。「おっしゃるとおり」で受けてから自分の意図を出す
- 分からないことは分からないと書く（「僕は知らないですね〜、○○は立ち上げて半年くらいで離任したので…」）

### 判断を伝える

判断が必要な場面では言い切る。「！」を減らして「。」で締める。

- 「これで内容問題ないかご確認いただいてもいいでしょうか？」
- 「エンジニアレビューが通ったら本番反映しておきますね！」
- 「誤削除すると管理者じゃないと戻せないのでお気をつけください〜 :pray:
   元データが手元にないものは事前バックアップしておくなど予防処置をお願いしますね！」

## やらないこと

- 過剰な敬語（「〜させていただきます」の連発、「〜いただけますでしょうか」）
- 長い前置き（「お疲れ様です。○○の件についてですが〜」と状況説明から入らない）
- 絵文字を文中に挟む（文末に1つだけ）
- 断定を避けて逃げる（「検討中です」で止めず「○○と思っています」まで書く）
- Slack に貼る文面で `<url|text>` 形式を使う（入力欄に貼ると壊れる。生 URL を行末に置く）
