# Notion のページ

個人メモ DB に `種別 = AIレポート` の行として作る。読み手は**この報告の経緯を何も知らない未来の自分**で、
Slack の通知から飛んできて、冒頭だけ読んで閉じるかもしれない。だから冒頭で結論が分かり、
目次から読みたいところへ飛べ、出てくる固有名詞はすべてリンクで元をたどれるようにする。

## プロパティ

| プロパティ | 型 | 入れるもの |
|---|---|---|
| `名前` | title | `<報告のタイトル>（YYYY-MM-DD）`。ルーティンは毎回同じタイトルに日付が付く形になる |
| `種別` | select | `AIレポート` |
| `出典URL` | url | 一番参照した資料 1 つ（無ければ空） |
| `Github Issue` | url | issue が起点なら |
| `初出コンテキスト` | select | 依頼の起点に合わせて `Slack` / `PR・コード` / `会議` / `ドキュメント` / `AIとの会話` |
| `date:登録日:start` | date | 今日 |

`ひとこと定義` / `読み・別名` / `社内での使われ方` / `公式定義` はユビキタス言語用なので空のまま。

ルーティンの報告は毎回新しいページを作る（前の回を書き換えない）。前回との比較が要る報告なら、
`notion-query-data-sources` で同じタイトルの直近のページを引き、その数字と比べる。
引くときは SQL モードではなく rows モード（`filter` と `sort`）を使う。SQL モードはプランによって利用上限があり、
1 日に何度も走るルーティンでは上限に当たって前回を引けなくなる。

## 本文

````markdown
<callout icon="📌" color="gray_bg">
**結論**: <1〜2 文>
**優先度**: 🔴 今日中に対応 / 🟡 今週中に確認 / 🟢 共有のみ
**次の行動**: <自分がやること。無ければ「なし」>
</callout>

<table-of-contents />

<h2 color="blue_bg">背景</h2>

<何を、なぜ報告するのか。依頼の文面と、対象の期間・範囲>

<h2 color="blue_bg">結果</h2>

<要点を箇条書き。事実には（[出典名](URL), YYYY-MM-DD）を付ける>

<h2 color="blue_bg">全体像</h2>

<この図で何が分かるかを 1 文>

```mermaid
<流れ・関係・推移を図にする>
```

<h2 color="blue_bg">詳細</h2>

<h3 color="blue_bg"><項目ごと></h3>

...

<h2 color="blue_bg">次の行動</h2>

- [ ] <やること>（期限・誰に）

<toggle heading="h3" color="blue_bg">集め方と前提

- 見た場所と検索語、対象期間
- 数え方（何を 1 件とみなしたか）
- 見ていないもの
</toggle>

<h2 color="blue_bg">参照</h2>

- [<資料名>](URL) — <何が書いてあるか 1 行>
````

### 見出し

- **見出しは `## ` ではなく `<h2 color="blue_bg">…</h2>` / `<h3 color="blue_bg">…</h3>` のタグで書き、すべてに背景色を付ける。**
  Notion の markdown では色の指定はタグの属性でしか書けない。書き終えたら全見出しに色が付いているか数えて確かめる
- 折りたたみは `<details>` ではなく `<toggle heading="h3" color="blue_bg">見出し` + 空行 + 中身 + `</toggle>`。
  `<details>` などの HTML タグは Notion では文字のまま残る
- 目次（`<table-of-contents />`）は結論の callout の直後に置く。見出しが少なくても置く

### 図を積極的に使う

文章で 3 文以上かかる関係は図にする。どれを使うかの目安:

| 伝えたいこと | 図 |
|---|---|
| 誰が何をどの順で（業務・データの流れ） | `sequenceDiagram` |
| 手順・分岐・判断 | `flowchart` |
| 状態の移り変わり（issue・PR・タスク） | `stateDiagram-v2` |
| 期間・予定 | `gantt` |
| 割合 | `pie` |
| 件数の推移 | `xychart-beta`（棒や線） |

図のラベルは日本語で短く書く。図の直前に「この図で何が分かるか」を 1 文添える
（図だけでは、何を見ればよいかが読み手に分からない）。

### ゼロコンテキストで読める書き方

yomiyasu スキルで推敲するのが基本。yomiyasu が使えないとき（クラウドのルーティン）は、次を自分で確かめる。

- 初めて出す社内用語・略語は、その場で一言説明する
- 番号や ID だけで物を指さない。「#123」ではなく「[#123 ○○の修正](URL)」のように名前とリンクを付ける
- issue・PR・Slack のスレッド・Notion のページ・ダッシュボード・クエリなど、読み手が開きたくなるものは
  すべてハイパーリンクにする。名前だけ・URL の生貼りにしない
- 相対の日付（「昨日」「先週」）は絶対の日付にする
- 1 文に 1 つのことだけ書く。主語を省くと誰の行動か分からなくなる箇所は主語を書く
- 推測は「推測」と明記し、事実と混ぜない

## 作り方

`notion-create-pages` の親に `data_source_url` を渡し、プロパティと本文を 1 回で渡す。
作ったら fetch して、見出しの色・目次・図が入っているか確かめる（mermaid が壊れていると
コードブロックのまま表示されるので、そのときは図の構文を直して `notion-update-page` で差し替える）。
