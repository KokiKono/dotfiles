# メモ DB への登録

登録先は ubiquitous-language と同じ個人メモ DB で、行は `種別` で見分ける。
このスキルが作るのは `種別 = イシュー検討メモ` の行だけ。

## プロパティ

| プロパティ | 型 | 入れるもの |
|---|---|---|
| `名前` | title | issue 起点なら `#<番号> <issue タイトル>`、それ以外は調べたテーマ |
| `種別` | select | `イシュー検討メモ` |
| `Github Issue` | url | 起点の issue の URL（あれば） |
| `出典URL` | url | 一番参照した資料 1 つ |
| `初出コンテキスト` | select | 起点に合わせて `Slack` / `PR・コード` / `会議` / `ドキュメント` / `AIとの会話` |
| `date:登録日:start` | date | 今日の日付 |

`ひとこと定義` / `読み・別名` / `社内での使われ方` / `公式定義` はユビキタス言語用なので空のままにする。

## 重複を見る

先に `notion-query-data-sources` で同じものが無いか確かめる。

- issue 起点: `"Github Issue" = '<url>'` で引く
- それ以外: `種別 = 'イシュー検討メモ'` の `名前` を引いて、同じテーマか見る

**あれば新しく作らず、既存ページの末尾に `## 追記（YYYY-MM-DD）` を足す。** 既存の記述は書き換えない。
前に書いた結論が覆った場合も、追記側に「○○ と書いたが、△△ だった」と残す。

## 本文

`template_url` を fetch して先頭の記載ルール callout をそのまま写し、続けて次の形で書く。
`template_id` でテンプレートを適用する手は使わない（適用が非同期で本文を同時に渡せず、空のページに後から追記する手順になるため）。

```markdown
- Github issue: <URL または空>
- 仕様Notion: <見つかった仕様ページへのリンク または空>

## 概要
<結論を 3〜5 行。これだけ読めば分かるように>

## 分かったこと
- <事実>（[出典名](URL), YYYY-MM-DD）

## 流れ
<業務やデータの流れがあれば mermaid の sequenceDiagram で>

## 食い違い・未確定
- ...

<details>
<summary>調べた範囲</summary>

- Slack: <検索語 / チャンネル>
- Notion: <検索語>
- GitHub: <検索語>
- kb: <検索語>
</details>
```

記載ルールに合わせ、概要だけで理解できるようにし、細かい根拠は折りたたみに入れる。
引用元は必ずハイパーリンクにする。
