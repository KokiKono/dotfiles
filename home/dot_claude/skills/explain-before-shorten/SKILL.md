# explain-before-shorten

AI に短く書かせると「受付と完了確認を分離する」「上限数は到達保証ではない」のような文が出てくる。
書いた側の頭の中では筋が通っているが、読み手には何がどう動くのかが残らない。原因は、言いたいことを
言葉にする前に字数を削っていること。このスキルは順序を逆にする。**先に口頭で説明するつもりで
全部言葉にし、そのあとで削る。**

着想元: https://zenn.dev/microsoft/articles/explain-before-shorten

「口頭で説明する」は中身を整理するための手段で、仕上がりを話し言葉にするという意味ではない。
文体は元の文書（です・ます / 常体、スライドの体言止めなど）に合わせる。専門用語を言い換える必要も、
すべての文に主語を補う必要もない。

## 手順

1. **伝えたいことを一文で決める。** 前後の文脈（スライドのタイトル、節の見出し、周りの箇条書き）を読み、
   この文が読み手に何を分かってほしいのかを一文で書く。ここが決まらないなら、直す前に聞く（下の「決められないとき」）。
2. **口頭での説明を字数を気にせず組み立てる。** 隣の席の人に聞かれたら何と答えるかを考える。
   「何が」「どうなる」「なぜ」「いつ・どんな条件で」を省かずに書き出す。
3. **話を分ける。** 仕組み・条件・例外・注意点が一文に混ざっていたら分ける。このとき、
   適用条件や制約（「〜の場合」「〜を除く」「〜まで」）を落とさない。短くしたときに真っ先に消えて、
   消えると嘘になる部分だから。
4. **意味を保ったまま削る。** 重複、回りくどい修飾、言わなくても分かる前置きを削る。製品やサービスの
   公式用語は崩さない。独自の略語や造語で縮めない（読み手に解読を押し付けるだけ）。
5. **短い文だけ読んで伝わるか確かめる。** 手順 1 の一文が読み取れるか、前後の文と用語が揃っているか、
   一文に話を詰め込みすぎていないかを見る。伝わらなければ手順 4 で削りすぎている。

否定から入る文（「〜を意味するわけではありません」）は、たいてい手順 1 が抜けている。
読み手が誤解しそうなことを先に打ち消すより、正しいことを先に言い、誤解しやすい点はそのあとに足す。

## 書き換えの例

| 元の文 | 何が足りないか | 直した文 |
| --- | --- | --- |
| 受付と完了確認を分離する | 「分離」で何がどう動くのかが分からない | 処理の終了を待たずに受付済みと返し、結果は後から問い合わせる |
| 上限数は到達保証ではない | 何の上限か、なぜ届かないのかがない | クォータなどの制約で、表の台数まで増やせない場合がある |
| 上限なしでも中断に備える | 何の上限か、何が中断するのかがない | 実行時間を無制限にしても、サービス側の更新などで処理が止まることがある |
| Completed は最後まで実行された状態です。入力不正が 0 件という意味ではありません。 | 否定が主役になっている | Completed はコードが最後まで実行されたことを示します。入力の検証結果は別に確認してください。 |

これは直し方の型を示す例で、文言をそのまま別の製品や構成に当てはめないこと。直した文に含めた原因や
条件（「クォータ」「サービス側の更新」）は、元の文脈から裏が取れたものに限る。

## 出力

- 直した文を先に出す。そのあと、何を補い何を削ったかを 1〜3 行で添える。手順 1〜5 の途中経過は
  見せなくてよい（ユーザーが求めたときだけ）。
- 複数の文を直すときは、元の文と直した文の対応が分かる形（表や前後の並記）にする。
- ファイルの中の文を直してと頼まれたら、提案を並べて承認を待たずにファイルを編集する。編集後は
  ファイルを読み直して、反映されたことと前後の文とのつながりを確かめる。確かめていないことを
  「直しました」と言わない。
- 直した結果が元より長くなるのは構わない。目的は短くすることではなく、短くても伝わることだから。
  スライドのように字数に制約があるなら、伝えたいこと 1 つに絞り、残りは別の行やノートに逃がす。

## 決められないとき

- 文の意味が複数に取れるなら、まず前後の文や関連ファイルを読む。それでも決まらなければ、
  候補を 2〜3 個挙げてどれのつもりかを聞く。
- 技術的な条件（上限値、保証の有無、どのバージョンからか）が文脈から確かめられないなら、
  推測で断定や保証を書き足さない。分からない部分は「（要確認: 〜）」と残してユーザーに伝える。

## 振り返り

ユーザーが直した文をさらに手直ししたら、その意図（もっと短く、用語を戻す、など）を同じ会話の
残りの文に生かす。頼まれない限り、このスキル自体に書き戻さない。
